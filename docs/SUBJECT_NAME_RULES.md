# 科目名を触るときのルールブック

科目名（`Subject.name`）の正規化・表示ロジックに手を入れる前に必ず読むこと。

## 1. 表記統一（DB保存時の自動正規化）

`Subject.name` は `@validates("name")`（`core.config.normalize_subject_name`）で、半角ローマ数字表記（`I`/`II`/`III`...）を全角ローマ数字（`Ⅰ`/`Ⅱ`/`Ⅲ`...）へ自動変換する。前後が英数字の場合は対象外とし、`AI`や`TOEIC`等の誤爆を防止している。

- `programing files/models.py` 側にも同じロジックを複製済み。新しい正規化ルールを追加する際は**両方の`models.py`を更新**すること。

## 2. LINE bot科目一覧のバリアント統合表示

`line_bot/handler.py`の科目一覧表示（`handle_course_list`）・テキスト検索では、**ベースの漢字部分が完全一致し末尾のアルファベット・数字だけが異なる科目は1行にまとめて表示する**。

例:
- `生物学各論A1/A2/C1/C2/D1/D2/E1/E2` → `生物学各論(A1/A2/C1/C2/D1/D2/E1/E2)`
- `微分積分1/2/3/4` → `微分積分(1/2/3/4)`

全角文字（`生物学各論Ｄ１`等）は`_FULLWIDTH_UPPER`でASCIIに正規化してから判定する。

末尾の数字の後ろに（遠隔）（再履修）以外の任意の説明書き括弧が付く科目名（例:
`環境基礎科学実験A1（主に地学）`）も、その説明書きが完全一致するメンバー同士でのみ
統合対象になる（2026-09-03、国際人間科学部「科目名(1/2)（説明書き）」をバリアント統合
方式に変換した際に`core/subject_variants.py`の`_VNUM`を拡張。無関係な科目同士が
説明書きの有無だけで誤って混ざることはない設計）。

**今後この一覧表示ロジックを触る・拡張する際もこの統合仕様を維持すること。**

### 適用範囲（重要）

この統合は**`line_bot/handler.py`のLINE bot表示専用**。DB上は常に個別のSubjectレコードのまま。

- 科目管理画面（admin）は元々このロジックを使っておらず、統合前の個別科目のまま選択・表示される。
- これは意図的な仕様であり、LINE bot一覧とadmin画面の見た目の違いを不具合と誤認しないこと。

## 3. 未解決の別問題（保留中・要注意）

DB内で科目名に「/」を含むSubjectは2グループに分かれる：

1. **外国語第1/2/3**（分類`教養(外国語第1/2/3)`）: `ドイツ語初級 A1/A2/A3/A4`のように、複数クォーター/複数クラスが1つのSubjectレコードにまとめられているcompound name。クォーター単位の担当教員の対応情報がDBに一切残っていない（`syllabi`/`schedules`が空でシラバスURLも導出不可）ため分割保留中。
   - 将来対応する場合の選択肢: (a)クォーターごとに空のSubjectとして分割し後で教員を手作業で振り直す (b)名前だけ簡略化 (c)シラバス再スクレイピングでクォーター単位の正しい情報を取得してから分割
2. **グローバルチャレンジ実習**（分類`教養(総合)`）: `グローバルチャレンジ実習(神戸GCP:カナダ.../フィールドワーク/前期/カナダ)`のように、スラッシュはプログラム内容の説明を区切る記号であり、1件1件が独立した単一プログラム。**分割対象ではない**（誤って分割しないよう注意）。
