## 機械工学科 専門科目の科目欠落（2026-07-14発見、全件解消）

学生便覧2026（`docs/学生便覧2026/binran_2026_koubu_kikai.txt`、別表第1ホ）に載っているのに
`subjects`テーブルに存在しなかった科目。`data/syllabus_ken_kyotsu.txt`（工学部全学科共通科目、
所属列は学科名なしの「工学部」）がユーザーから提供され6件投入済み：

- ~~知的財産入門~~ → 投入済み（id=4702, faculty="工学部"）

- ~~複素関数論~~ → `複素関数論（市民・機械）`として投入済み（id=4690）。noteもこの実名に修正済み
- ~~常微分方程式論~~ → `常微分方程式論（機械）`として投入済み（id=4703）。noteもこの実名に修正済み
- ~~偏微分方程式~~ → `偏微分方程式（機械）`として投入済み（id=4682）。noteもこの実名に修正済み
- ~~フーリエ解析~~ → `フーリエ解析（機械）`として投入済み（id=4705）。noteもこの実名に修正済み

残り4件はシラバスデータ（時間割コード・担当教員・曜日時限）が無いまま、ユーザー指示で
`subjects`テーブルにcredits/classificationのみの仮登録とした（`course_sections`/`syllabi`/`schedules`は無し。
時間割コマ表示・シラバスリンクは無いが、単位チェッカーの対象科目名としては機能する）：

### 未解決・要フォローアップ

1. **「実践簿記１〜４」が単位群判定で第3群（`senmon3`）扱いになっている**
   `core/seiseki.py`の`_SENMON2_PREFIX = ('簿記',)`は「簿記」で始まる科目名のみ前方一致するが、
   2件の実サンプルはいずれも科目名が「実践簿記１」「実践簿記２」「実践簿記３」で「簿記」から
   始まらないため対象外。dev DBでも`subjects.classification`が「第3群科目」で登録済み
   （`senmon_group`は未設定）。これが便覧上正しい分類なのか、新カリで科目名が変わっただけで
   本来は第2群相当なのかは学生便覧 別表第2（履修要件）を確認しないと判断できない。
   → 便覧PDFが`docs/`に見当たらないため未着手。便覧が手に入り次第、第2群科目一覧と
   突合して`_SENMON2_EXACT`／`_SENMON2_PREFIX`or DBの`senmon_group`を修正すること。

2. **外国語第Ⅰ・第Ⅱの小見出しが丸括弧でなく角括弧で表現される成績表がある（実害なし）**
   `docs/sosuke_seiseki.txt`では`（外国語系　）`の下に`［外国語第Ⅰ］`／`［外国語第Ⅱ］`という
   角括弧`［　］`の小見出しがある。`extract_seiseki_raw()`の`sub_m`正規表現は丸括弧
   `（　）`のみ対応のためこの小見出しはcurrent_secに反映されないが、英語/第二外国語の判定は
   科目名自体（`Academic English`接頭辞・言語名接頭辞）から行っているため実害は無い。
   将来「外国語第Ⅲ」等をラベル起点で判別する必要が出た場合は角括弧にも対応すること。

3. **`sonota`のうち外国語第Ⅱ（C1/C2クラス）・外国語第Ⅲの仕分けは未対応**
   `credit_requirements.sonota`のnoteに「外国語第Ⅱ（C1，C2），外国語第Ⅲ」が含まれる旨の
   記載があるが、通常の外国語第Ⅱクラスとの区別方法が実サンプルから判別できず未実装。
   該当データを含む成績表サンプルが手に入り次第対応すること。

4. **「経営学部科目」区分の用途が未確認**
   両サンプルとも区分表に「経営学部科目 0.0」という行があるが、`credit_requirements`に
   対応する`category_id`が無く、コードでも参照していない。経営学部生自身が経営学部科目を
   履修するケースは通常発生しないため実害は無いと思われるが、意味が確認できていない。

5. **`jinbun_shizen`（人文系＋自然系 計、8単位要件）合算行が旧カリ成績表で常に0になる → 対応不要（ユーザー判断）**
   旧カリ形式（人文/自然/社会/総合系の内訳が無く「総合教養科目」で一括集計）の成績表は、
   フォールバックとして`sougou`（総合系）へ一括計上するようにしたため（項目1参照）、
   `jinbun`と`shizen`は常に0のまま。その結果`jinbun_shizen`（`jinbun`+`shizen`の合算）も
   常に0になり、実際は教養単位を取得していても8単位要件が永遠に未達成表示になる。
   内訳が成績表から判別できない以上、これ以上の精度向上は困難なため、2026-07-14時点で
   ユーザー判断により対応不要と結論。再検討する場合は`docs/Mr.sora_seiseki.pdf`が具体例。
